# 英语学习打卡网站

一个面向个人长期语言学习的“有效投入时间”记录网站。它不按自然日倒数，也不因为漏学一天惩罚用户；只有真正完成学习并入账后，剩余小时才会减少。

本项目的需求来源于 Codex 对话 `019fc411-f805-7821-b9bd-cff3ebb5f2f5`。本文档是该对话中学习目标、训练方法和已有网页迭代经验的整理，也是后续产品设计与开发的需求基线。

## 1. 为什么要做

用户当前的英语水平约为 Lexile 925L，主要问题不是单纯“词汇量不够”，而是一个相互影响的学习闭环：

- 长文生词过多会造成认知超载，阅读从理解内容变成逐词解码，因此容易失去耐心。
- 不少词汇只停留在“看到认识”的被动层，缺少主动提取训练，长期感觉词汇没有增长。
- 阅读时认识的词，在真实语流中可能无法识别，说明文字索引与声音索引没有连通。
- 口语卡壳通常不是完全不知道，而是词汇和表达尚未形成可以快速调用的提取通路。
- 复杂、强度过高的计划难以坚持；以日期为目标的倒计时在中断后容易制造失败感和负罪感。

因此，本网站不能只是一个日历打卡器。它需要让用户看到长期投入正在积累，并持续提醒用户完成“输入 → 声音识别 → 主动提取 → 输出”的训练闭环。

## 2. 产品目标

### 核心目标

帮助用户用可持续、低负罪感的方式累计有效学习时间，最终达到：

- 英语：从当前约 B1 中段提升到 B2 上段，能够与英语母语者进行基本流利的日常对话。
- 日语：在现有 N4–N3 左右的基础上，逐步达到无字幕理解大部分日常影视内容，并能进行较流利的日常对话。

### 产品原则

1. **倒数投入量，不倒数日期**：英语目标为 500 小时。没学习时进度只是暂停，不显示“落后”或“失败”。
2. **主次清晰、两种语言分账**：英语是主项，日语是副项；任何语言的投入只能减少该语言自己的剩余小时。
3. **先保证频率，再追求强度**：忙碌时完成最低不掉线项目也值得记录，不用补签式惩罚。
4. **记录必须轻量**：一次入账应只需选择日期、训练项目和分钟数。
5. **进度必须可验证**：小时数提供即时反馈，里程碑用真实能力验收，不以“累计天数”冒充能力提升。
6. **同一材料完成多个训练动作**：精听、阅读、跟读、复述和收词尽量围绕同一内容展开，提高转化效率。

## 3. 语言目标与学习方案

### 英语：500 小时主目标

建议每日投入约 45 分钟：

| 项目 | 建议时长 | 方法 |
| --- | ---: | --- |
| 精听 ★ | 15–20 分钟 | 使用带 transcript 的 1–2 分钟材料：盲听 → 逐句辨音 → 对文本标记 → 跟读 |
| 泛听 | 10 分钟 | 听已经精听过或正在精听的材料，训练实时处理，只抓大意 |
| 阅读 | 10 分钟 | 阅读约 925L 的短新闻；第一遍不查词，第二遍只处理关键障碍词 |
| 复述 ★ | 5 分钟 | 合上材料，用英语复述 3–5 句；卡住的表达是主动词汇候选 |
| Anki | 5 分钟 | 使用提取卡片说出句子，而不是只做单词识别 |

精听材料的毕业标准：盲听一遍能够实时理解约 95%，并能识别此前标记的连读、弱读和熟词生音。通常一份材料练习 2–4 天；连续 5–6 天仍大面积听不懂，说明材料过难，应主动降级。

英语里程碑：

| 累计投入 | 能力验收 |
| ---: | --- |
| 100h | 盲听慢速材料一遍理解约 80%；能就熟悉话题连续说 2 分钟 |
| 200h | 能跟上 6 Minute English；能与人对话 10 分钟而不中断 |
| 300h | 常速播客理解约 70%；能即兴谈论工作话题 5 分钟 |
| 400h | 无字幕访谈能理解大意；对话中可以自我纠正而不是直接卡住 |
| 500h | 与母语者进行日常对话基本无障碍 |

### 日语：800 小时独立副目标

建议每日投入 15–30 分钟，不挤占英语主项：

| 项目 | 建议时长 | 方法 |
| --- | ---: | --- |
| 影视精听 ★ | 10–15 分钟 | 使用看过的日剧或电影 1–3 分钟片段：盲听 → 逐句 → 对日文字幕 → 跟读 |
| 台词跟读 ★ | 5 分钟 | 模仿精听片段，把地道表达搬进口语 |
| 复述 | 5 分钟 | 用日语复述 3–5 句剧情，找出主动表达缺口 |
| 泛听 | 5–10 分钟，可选 | 用影视或播客维持每日接触 |

日语训练要重点收集口语缩约和音变，例如 `〜ちゃう`、`なきゃ`、`とく`。日语与英语每天都可以练，但不做机械的五五分配；英语保持主项，日语保持高频、低剂量。

日语里程碑：

| 累计投入 | 能力验收 |
| ---: | --- |
| 200h | 巩固 N3；慢速日剧片段盲听约 70%；日常话题连续说 3 分钟 |
| 400h | 接近 N2；常速生活场景理解约 60%–70%；日常对话能够持续 |
| 600h | 无字幕电影能理解大意；口语开始稳定使用中级表达 |
| 800h | 无字幕影视理解约 80% 以上；与日本人日常对话基本无障碍 |

## 4. MVP 功能范围

### 4.1 双语言页签

- 顶部提供“英语 / 日语”页签，默认进入英语。
- 页签必须可点击、可用键盘操作，并清楚显示当前语言。
- 两个页面使用一致的信息结构，但拥有独立目标、训练项目、统计、里程碑和记录。
- 切换页签不得刷新页面或丢失尚未保存的数据。

### 4.2 主倒计时与进度

每个语言页面都需要展示：

- 剩余小时数（最显眼的主数字）。
- 已投入分钟数与折算小时数。
- 完成百分比。
- 带里程碑刻度的进度条。
- 未学习时保持原状，不出现逾期、欠账、失败或补签提示。

英语总目标固定为 500 小时，日语总目标固定为 800 小时。完成度不得超过 100%，剩余时间不得小于 0。

### 4.3 学习入账

一条记录至少包含：

- 唯一 ID
- 日期
- 语言：英语或日语
- 训练项目
- 学习分钟数
- 创建时间

英语训练项目：精听、泛听、阅读、复述、Anki。

日语训练项目：影视精听、台词跟读、复述、泛听。

交互要求：

- 默认日期为今天。
- 支持手动输入分钟数。
- 提供 15 / 30 / 45 / 60 分钟快捷按钮。
- Enter 可以提交。
- 非法、空值、负数或 0 不得入账，并应给出清楚的行内提示。
- 成功后立即更新倒计时、统计、项目分布、里程碑和最近记录。

### 4.4 学习统计

每种语言独立展示：

- 累计学习天数
- 日均分钟数
- 当前连续天数
- 根据已有日均投入估算的完成日期；没有数据时显示 `—`
- 各训练项目累计时长和占比
- 当前月份的学习热力图：按语言汇总每天分钟数，颜色随 0、1–14、15–29、30–59、60 分钟以上逐级加深，并同时显示具体分钟数

连续天数是辅助反馈，不应成为惩罚机制。断链后不要使用红色警告或失败文案。

热力图回答“这个月哪些天学习、投入强度如何”，不替代项目构成分析。后续若增加每日时间分布，应使用按训练项目堆叠的日柱状图，回答“每天把时间花在了什么项目上”；累计项目分布继续回答“到目前为止整体训练结构如何”。

### 4.5 里程碑验收

- 页面始终展示全部里程碑，不能因为当前无数据而呈现空白区域。
- 达到对应累计小时后自动点亮。
- 每项必须同时显示目标小时与能力验收描述。
- 自动点亮表示“到达验收时点”，不等同于用户已经通过能力测试；后续可以扩展手动验收状态。

### 4.6 最近记录与数据管理

- 当前语言只显示自己的记录，按日期和创建时间倒序排列。
- 记录应显示日期、项目、分钟数，并允许单条删除。
- 无记录时显示友好的空状态，例如“还没有记录，今天学 5 分钟也算入账”。
- 清空全部数据必须二次确认，并明确说明不可恢复。
- 必须登录且保持联网才能新增、删除或清空记录；离线时不建立待同步队列。
- 数据保存在 Supabase 云数据库中，按账号隔离，刷新或更换设备登录后仍然存在。
- 首次登录会检查旧版浏览器数据，并把 `en500h_v1` 与 `lang_countdown_v2` 中的有效记录幂等上传到当前账号；旧本地副本不会自动删除。

### 4.7 学习方法提示

页面应保留简洁的每日推荐时间表，让用户不仅知道“记了多少”，也知道“今天该做什么”。学习方法说明不要压过核心入账操作，可以折叠、分区或放在统计之后。

## 5. 体验与视觉方向

- 这是一个安静、可信、长期使用的个人工具，不做竞技排行榜或强刺激游戏化。
- 视觉以清晰、克制、留白充足为主；英语和日语可以使用不同强调色，但整体仍属于同一产品。
- 首屏优先展示语言切换、剩余小时、进度和快速入账。
- 中文是主要界面语言；数字、小时、分钟和百分比需要易扫读。
- 同时支持桌面端与手机端，手机上不能出现横向溢出，表单控件要便于触摸。
- 动效只用于进度变化、成功反馈和页签切换，并尊重 `prefers-reduced-motion`。
- 不使用羞辱、制造焦虑或暗示落后的文案。

## 6. 数据计算口径

- `languageTotalMinutes = sum(records where language matches)`
- `remainingMinutes = max(0, targetMinutes - languageTotalMinutes)`
- `completion = min(100, languageTotalMinutes / targetMinutes × 100)`
- 学习天数按该语言存在记录的去重自然日计算。
- 日均分钟按 `languageTotalMinutes / 学习天数` 计算，不把未学习的自然日计入分母。
- 当前连续天数按本地日期计算；今天没有记录时，允许从昨天开始计算当前有效连续段。
- 项目占比的分母只使用当前语言的累计分钟数。
- 预计完成日仅作估算，使用当前语言的日均分钟，不得混入另一种语言的数据。

- [ ] 英语与日语页签都能通过点击和键盘切换。
- [ ] 英语入账只更新英语数据，日语入账只更新日语数据。
- [ ] 首次打开、无记录时，两个语言页面的里程碑和空状态均正常显示。
- [ ] 新增、删除、刷新页面后，所有统计结果保持正确。
- [ ] 快捷分钟按钮和 Enter 提交可用，非法输入不会写入。
- [ ] 各项目时间分布之和与当前语言累计时长一致。
- [ ] 本月热力图按当前语言和本地月份汇总；同一天多笔记录会合并分钟数，英语与日语不串账。
- [ ] 达到里程碑阈值时正确点亮，目标完成后不会出现负数或超过 100%。
- [ ] 清空数据有确认步骤；取消确认不会改变任何数据。
- [ ] 旧版数据迁移不会重复导入，也不会丢失记录。
- [ ] 在常见手机宽度下可完整使用，没有横向滚动和难以点击的控件。
- [ ] 浏览器控制台无语法错误和运行时错误。

## 8. 暂不属于当前版本

以下方向可以后续扩展，但不应阻塞首版：

- 每周复盘、能力验收表单和历史快照
- Ground News 选题与约 925L 难度的自动改写阅读材料
- 配套音频、transcript 和精听标记工具
- Anki 导出或主动词汇卡片管理
- PWA、离线安装、数据导入导出与备份
- 真人或 AI 口语练习的预约、记录和反馈

## 9. 账号、云端数据与安全

- 账号认证和学习记录使用 Supabase Auth 与 Postgres。
- 前端仅包含 Supabase 的公开项目 URL 和 publishable key；这类浏览器端标识符不是数据库管理密钥。
- `study_entries` 已启用 Row Level Security（RLS）。登录用户只能读取、创建、修改和删除 `user_id` 等于自己的记录；匿名请求看不到记录，也无法写入。
- 数据库密码、secret/service-role key 等管理凭据不得写入前端、Git 仓库或 Vercel 构建配置。
- 表结构和 RLS 策略保存在 `supabase/migrations/20260808_create_study_entries.sql`，便于审计和重建。

第一次使用：打开线上网站，点击“注册账号”，按确认邮件完成邮箱验证，再回到网站登录。之后同一账号可在不同设备使用。若注册时 Supabase 返回了即时会话，网站会直接进入已登录状态。

## 10. 本地运行

当前版本是静态单页应用，入口为 `index.html`，在浏览器中通过 Supabase JS 访问云端。运行和使用都需要联网。

可以直接打开 `index.html`，或在项目目录启动任意静态文件服务器，例如：

```bash
python3 -m http.server 4173
```

随后访问 `http://localhost:4173`。该地址已加入 Supabase 登录重定向白名单。生产站点为 [500Hours](https://500-hours-delta.vercel.app/)。

目前没有构建步骤或包管理依赖。修改后至少执行一次脚本语法检查，并在真实浏览器完成“注册/登录 → 切换语言 → 入账 → 刷新 → 删除 → 退出”的验证。后续开发应继续以本 README 的产品目标和验收清单为准；具体工程规范见 [AGENTS.md](./AGENTS.md)。
